# Тестик

Telegram Mini App: React + TypeScript + Vite + Telegram UI.

## Концепция

Есть два готовых теста: «Каким человеком вы меня видите?» и «Какой у меня вайб?». Пользователь выбирает готовый тест или составляет собственный — это не создание теста из шаблона.

Конструктор пользовательских тестов открывается по /create. Его ограничения хранятся в src/config/testLimits.ts:

- максимум 10 вопросов;
- от 2 до 6 вариантов ответа на каждый вопрос.

На главной есть кнопка «Создать свой тест». Редактор позволяет добавить название, вопросы и варианты, удалить лишние строки и сохранить незаконченный черновик на этом устройстве. Кнопка «Сохранить черновик» записывает его в localStorage; сохранённые изменения восстанавливаются после перезагрузки и возврата в редактор. Несохранённые изменения теряются при уходе со страницы. Личные ссылки, сохранение ответов друзей и статистика ещё не подключены. Серверная проверка Telegram доступна через /api/me.

## Запуск

```sh
npm install
npm run dev
```

Открой адрес Vite. В браузере начальная тема соответствует системной, переключатель позволяет проверить обе темы. В Telegram оформление задаёт клиент, панель браузерного предпросмотра скрыта.

`npm run dev` запускает приложение и API вместе. API слушает http://127.0.0.1:3001, Vite перенаправляет запросы `/api` на этот адрес. Для отдельного запуска есть `npm run dev:web` и `npm run dev:api`.

В панели браузерного предпросмотра отображается состояние связи с API. Кнопка «Проверить связь» повторяет проверку, в том числе после запуска сервера. Если API выключен, черновики и предпросмотр готовых тестов остаются доступны.

Проверка API: `GET /api/health` возвращает `{"status":"ok","service":"testik-api"}`. Этот маршрут проверяет доступность сервера, а не базы данных.

`npm run build` собирает React-приложение в dist и API в dist-server. `npm run start:api` запускает собранный сервер. Прокси `/api` сейчас настроен для разработки; при публикации потребуется настроить его на хостинге. `npm run test:api` проверяет HTTP-контракт API через встроенный Fastify inject: https://fastify.dev/docs/latest/Guides/Testing/.

```sh
npm run build
npm run preview
```

Проект совместим с Node.js 20.18.1. React 18 выбран под peerDependencies Telegram UI, Vite 6 — под установленную версию Node.js.

## PostgreSQL в Docker

База запускается через compose.yaml. Нужен запущенный Docker Desktop с Linux containers; отдельная установка PostgreSQL в Windows не требуется.

```sh
npm run db:up
npm run db:status
```

При первом запуске Docker загрузит официальный образ postgres:18-alpine. Команда db:up ждёт готовности PostgreSQL. Подключение с компьютера: 127.0.0.1:5433, база testik, пользователь testik. Пароль хранится только в локальном .env. Порт 5433 выбран, чтобы отделить эту базу от возможного PostgreSQL на стандартном порту 5432. Порт опубликован только на локальном интерфейсе.

Это конфигурация для локальной разработки. В .env.example перечислены переменные, пароль и DATABASE_URL оставлены пустыми. Для нового окружения скопируй файл в .env и заполни оба значения; .env исключён из Git. Формат строки: postgresql://USER:PASSWORD@127.0.0.1:5433/DB?schema=public. Специальные символы в пароле нужно закодировать для URL. Compose требует непустой POSTGRES_PASSWORD и не использует пароль по умолчанию. API читает DATABASE_URL из локального .env.

Данные находятся в Docker volume testik_postgres_data. В PostgreSQL 18 он смонтирован в /var/lib/postgresql согласно документации образа: https://github.com/docker-library/docs/tree/master/postgres#pgdata.

```sh
npm run db:logs
npm run db:down
```

db:down останавливает и удаляет контейнер проекта, сохраняя volume с данными. Следующий db:up использует прежнюю базу. Не добавляй флаг -v к команде down, если данные нужно сохранить. Изменение POSTGRES_USER, POSTGRES_PASSWORD и POSTGRES_DB в .env не меняет пользователей и базы в уже инициализированном volume.

## Prisma и первая таблица

Схема хранится в prisma/schema.prisma, изменения таблиц — в prisma/migrations. Используется Prisma 6, совместимая с установленным Node.js 20.18.1: https://www.prisma.io/docs/orm/reference/system-requirements#prisma-orm-v6.

На новом окружении после запуска базы:

```sh
npm run db:generate
npm run db:deploy
npm run db:check
npm run dev
```

db:deploy применяет уже сохранённые миграции. При изменении схемы разработчиком используется npm run db:migrate -- --name название_изменения. Сборка API также генерирует Prisma Client. Сгенерированный клиент находится в node_modules и не коммитится. Prisma форматирует свою схему отдельно от Prettier.

Таблица personal_tests хранит:

- ownerTelegramId — Telegram ID автора;
- subjectName — необязательное имя человека, о котором отвечают;
- title, status, version — название, состояние DRAFT/PUBLISHED/ARCHIVED и версию;
- source — READY или CUSTOM, для готового теста есть readyTestId и readyTestVersion;
- shareCode — уникальный случайный UUID для будущей ссылки;
- content — снимок вопросов, вариантов и, для готового теста, баллов и результатов в JSONB;
- createdAt и updatedAt — время создания и изменения.

API проверяет соединение при запуске и закрывает Prisma Client при остановке. npm run db:check отдельно проверяет соединение и наличие таблицы без добавления данных. /api/health по-прежнему проверяет доступность API, не выполняя запрос в базу при каждом вызове.

npm run test:db проверяет запись и чтение JSONB, точность Telegram ID, значения по умолчанию и уникальность кода ссылки в настоящей базе. Все созданные проверкой записи откатываются транзакциями и не остаются в таблице. npm run test:api проверяет запуск и закрытие соединения с подменённым клиентом, без обращения к PostgreSQL.

Сохранение из редактора и таблица ответов пока не реализованы. Проверка Telegram initData подготовлена; ownerTelegramId будет браться из проверенной сервером личности. Ограничения вопросов и структура JSONB будут проверяться сервером при сохранении.

## Структура

```text
src/
    app/            — корневой компонент и оформление приложения
    components/     — каждый общий компонент в своей папке со своими стилями
    pages/          — каждый экран в своей папке
    hooks/          — интеграция с Telegram и состояние конструктора
    data/           — готовые тесты, типы и модель черновика
    config/         — ограничения собственного теста
    main.tsx        — точка входа
    styles.css      — базовые глобальные стили
```

server/ содержит отдельное TypeScript-приложение Fastify: app.ts создаёт сервер, index.ts запускает его, routes/ содержит HTTP-маршруты. Сервер собирается с tsconfig.server.json.

Готовые тесты открываются по /tests/person и /tests/vibe. Есть возврат на главную, обработка неизвестного теста и нативная кнопка назад Telegram.

## Стиль кода

Prettier использует 4 пробела, одинарные кавычки в JavaScript/TypeScript и ширину строки 100 символов. ESLint проверяет TypeScript, React hooks и ограничения Fast Refresh. eslint-config-prettier отключает конфликтующие правила оформления.

```sh
npm run lint
npm run lint:fix
npm run format
npm run format:check
```

.editorconfig задаёт отступы для редакторов. В .vscode включены форматирование при сохранении и рекомендуемые расширения Prettier/ESLint.

## Проверка в Telegram

Подключён официальный Telegram WebApp API: ready/expand, themeChanged, платформа iOS/base, стабильная высота и безопасные отступы.

Для проверки в клиенте нужен бот разработки и HTTPS-адрес, настроенный в BotFather. При публикации хостинг должен возвращать index.html для маршрутов приложения (SPA fallback).

Наличие initData на клиенте определяет среду запуска. Сервер подтверждает личность отдельно: проверяет HMAC-SHA-256 подпись по алгоритму Telegram, auth_date и структуру пользователя.

Добавь BOT_TOKEN своего бота только в локальный .env и перезапусти API. В .env.example значение пустое; переменная не должна иметь префикс VITE_, попадать в клиентский код или коммититься. Без токена API и база продолжают работать, но защищённый маршрут не подтверждает вход.

GET /api/me принимает Authorization: tma <Telegram.WebApp.initData>. ID возвращается строкой. При отсутствии или неверных данных сервер отвечает 401, при ненастроенном BOT_TOKEN — 503. Принимаются данные не старше одного часа; допускается расхождение часов на 30 секунд в будущее. После истечения срока нужно заново открыть Mini App. Повторяющиеся параметры отклоняются, сравнение подписи выполняется через timingSafeEqual, ответы маршрута не кешируются.

src/api/currentUser.ts содержит getCurrentUser для следующего шага интерфейса: он отправляет initData из Telegram, не использует initDataUnsafe и не сохраняет данные авторизации в localStorage. Сам интерфейс пока не вызывает маршрут. Обычный браузер остаётся доступен для редактирования и предпросмотра локальных тестов.

npm run test:api проверяет правильную подпись, подмену пользователя, срок действия, неверные форматы и отсутствие конфигурации. Подписи в тестах создаются отдельно через Web Crypto с синтетическим тестовым ключом, без настоящего токена бота. Полная проверка через Telegram требует своего бота и HTTPS-адреса Mini App.

Алгоритм Telegram: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app.

Документация API: https://core.telegram.org/bots/webapps#initializing-mini-apps

## Импорты

Компоненты и страницы экспортируются через index.ts своих папок. Например, в App можно писать:

```ts
import { BackNavigation, BrowserPreview } from '../components';
import { HomePage, TestDetailsPage, NotFoundPage } from '../pages';
import { useTelegram, useTelegramBackButton } from '../hooks';
```

Внутри компонента используем отдельную папку соседнего компонента, чтобы не создавать циклический импорт через общий index.ts. Единственный компонент App находится в src/app/App.tsx и экспортируется через src/app/index.ts. Точка входа main.tsx импортирует его из папки app.

## Предпросмотр собственного теста

Кнопка «Посмотреть тест» проверяет название, тексты вопросов и все варианты ответа, включая строки из одних пробелов. Незаконченный черновик по-прежнему можно сохранить.

На /create/preview доступно пробное прохождение: один ответ на вопрос, прогресс, переход назад с сохранением выбранного ответа и завершение просмотра. Ответы предпросмотра не отправляются и не сохраняются.

При переходе из предпросмотра в редактор текущие поля сохраняются в памяти. Сам предпросмотр не записывает черновик на устройство: для восстановления после перезагрузки нужно нажать «Сохранить черновик». Прямая ссылка на предпросмотр использует последний сохранённый черновик; если он незаполнен, показывается возврат к редактированию.

## Хранение тестов

Готовые тесты находятся в src/data/readyTests.json: описание, вопросы, варианты, устойчивые ID и номер версии. Типы вопросов общие с пользовательскими тестами. Количество вопросов вычисляется по массиву, отдельно его хранить не нужно. Кнопка «Посмотреть вопросы» на странице готового теста открывает пробное прохождение.

ownerDescription используется на странице выбора теста, participantDescription — в начале предпросмотра. shareText сохранён для будущей отправки личной ссылки; отправка пока не подключена.

Готовые тесты используют resultType: maxScore. Баллы points выбранных вариантов суммируются по ID из results. На завершении предпросмотра показываются типы с максимальной суммой; при равенстве показываются все совпавшие типы. Отсутствующая категория в points даёт ноль баллов. Возврат к вопросу и замена ответа учитывают только последний выбор. Для пользовательского теста категории и баллы не добавляются: он по-прежнему завершает просмотр подтверждением.

Вопросы в JSON — стартовая редакция для проверки продукта. При изменении содержания готового теста потребуется повысить version.

Подготовлена таблица личных тестов в PostgreSQL. Далее подключим сохранение через API:

- пользователя будем связывать с проверенным Telegram ID;
- личный тест будет хранить автора, название, имя человека, о котором отвечают, статус, случайный код ссылки и вопросы с вариантами в JSONB;
- при выборе готового теста сервер зафиксирует его ID, версию и снимок вопросов для личной ссылки;
- собственный тест будет сохраняться из редактора после серверной проверки лимитов и содержания;
- после публикации вопросы не меняются, для правок создаётся новая версия;
- ответы будут храниться отдельными записями с ограничением одного прохождения на пользователя и личный тест;
- статистику будет получать только автор, без имён отвечавших.

JSONB позволяет хранить небольшую структуру вопросов внутри строки PostgreSQL. Автор, код ссылки и статус остаются отдельными колонками. API подключён к базе через Prisma; localStorage пока хранит один черновик на устройстве, а редактор ещё не сохраняет его в базу.

Имя человека будет частью личного теста, а готовый JSON останется общим. Формулировки с именем добавим отдельным шагом. Снимок опубликованного готового теста будет включать вопросы, баллы и результаты, чтобы будущие изменения JSON не меняли уже собранные ответы.

Документация PostgreSQL: https://www.postgresql.org/docs/current/datatype-json.html
